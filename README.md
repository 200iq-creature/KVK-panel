# KVK Panel

Веб-панель для Xray-core: клиенты, подписки, инбаунды (VLESS Reality / XHTTP / WS / gRPC, VMess, Trojan, Shadowsocks 2022, Hysteria2, TUIC v5, AmneziaWG, MASQUE), бот-магазин, Telegram-прокси (MTProto/SOCKS), связка серверов, бэкапы, 2FA, фильтрация рекламы, WARP, миграция с 3x-ui/Remnawave, сертификаты Let's Encrypt для доменов и IP, логи. Версию Xray можно выбрать, обновить и откатить прямо из панели.

## Установка

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/200iq-creature/KVK-panel/main/install.sh)
```

Установщик:
- скачивает бинарник из GitHub Releases (если релиза нет — собирает из исходников временным Go);
- задаёт случайные порт, секретный путь, логин и пароль и выводит их в конце;
- открывает порт панели (и 80/443 для сертификатов) в ufw / firewalld / iptables;
- ставит последнюю версию Xray и geo-файлы;
- создаёт службу systemd `kvk-panel` и меню управления `kvk`.

Переменные окружения: `KVK_PORT`, `KVK_USER`, `KVK_PASS`, `KVK_PATH`, `KVK_XRAY_VERSION`, `KVK_FROM_SOURCE=1`.

Обновление: `kvk update` или кнопка в «Настройках». Удаление: `kvk uninstall`.

## Сайт

Раздел «Сайт» (раньше «VLESS за минуту») настраивает сайт-прикрытие и подключения за ним. Нужен только домен, лучше два или три.

1. Выберите домены из раздела «Домены» (кнопки над полем ввода) или впишите новые, и отметьте один как «маску» (SNI) для Reality. Если на домене открывается панель, рядом написано, какого сервера. Во всех списках доменов (Домены, сертификат инбаунда) домен сайта подписан «сайт-прикрытие», а домен панели подписан «панель «имя сервера»». Для доменов сайта рекомендуем включить один как «маску» (SNI) для Reality. Для доменов сайта рекомендуем включить **Cloudflare-прокси (оранжевое облако)**: так сайт будет за Cloudflare, IP сервера не виден, а подписка получит запасной вход через CDN.
2. Если хотите, укажите API-токен Cloudflare (Edit zone DNS + Zone Settings · Edit). Панель сама создаст A-записи, включит облако и выставит SSL Full (strict).
3. Нажмите «Настроить всё».

Что сделает панель:
- поднимет на всех доменах сайт-прикрытие из папки [`fake/`](fake). Это генеративная «студия», и рисунок с текстами зависит от домена. Можно заменить своим HTML прямо в панели;
- создаст **VLESS Reality (Vision)** на 443. Чужие подключения уходят на сайт-прикрытие, поэтому сервер выглядит как обычный HTTPS-сайт;
- создаст **VLESS XHTTP за сайтом**: вход через Cloudflare CDN, который работает даже при блокировке IP;
- выпустит и будет продлевать сертификаты Let's Encrypt, откроет порты, проверит, что всё отвечает, и выдаст ссылки с подпиской.

Удалить автонастройку можно одной кнопкой. Клиенты и сертификаты при этом останутся.

## Бесплатные домены

Нет своего домена — в «Доменах» нажмите **«Бесплатный домен»**. Домен ничего не стоит, аккаунт не нужен; панель сама направит имя на сервер и выпустит сертификат Let's Encrypt.

| Сервис | Имя | Что нужно сделать |
|---|---|---|
| sslip.io | `site-93-184-216-34.sslip.io` | ничего — имя появляется сразу (IP сервера записан в имени) |
| nip.io | `site-93-184-216-34.nip.io` | ничего — запасной вариант того же типа |
| freemyip.com | `любое-имя.freemyip.com` | один клик «Claim it!» на их сайте и вставить показанную ссылку |
| myaddr.tools | `любое-имя.myaddr.tools` | один клик «Claim» на их сайте и вставить секретный ключ |

На freemyip.com и myaddr.tools имя занимают на их странице: там стоит проверка «я не робот», которую нельзя пройти за пользователя. Регистрации, почты и пароля нет. Дальше всё делает панель:
- направляет имя на IP сервера;
- обновляет его, чтобы оно не истекло (myaddr.tools удаляет имена без обновлений через 90 дней, freemyip.com — через год);
- при восстановлении конфигурации на новом сервере переносит имя туда (с галочкой DNS) или кнопкой «Направить сюда».

Имена sslip.io и nip.io содержат IP, поэтому после переезда сервера создайте новое. Бесплатные домены нельзя поставить за прокси Cloudflare: на них работает Reality, а CDN-вход — только на своём домене.

## TUIC, AmneziaWG и MASQUE

Создаются в «Инбаундах», как остальные протоколы.

- **TUIC v5** (QUIC/UDP, всегда TLS). Сервер встроен в панель: используется реализация sing-quic, та же, что в sing-box. Обновляется вместе с панелью. Клиенты получают ссылку `tuic://`, а в Clash-подписке — прокси `tuic`. Подходят Hiddify, NekoBox, Karing, sing-box, v2rayN, Clash Meta.
- **AmneziaWG** (UDP). WireGuard с обфускацией Jc/Jmin/Jmax/S1–S4/H1–H4/I1–I5. Сервер на amneziawg-go тоже встроен в панель и работает в userspace: модуль ядра, TUN и NAT не нужны. Параметры обфускации генерируются случайно. Каждый клиент получает свой ключ и адрес. Его `.conf` и QR-код есть в карточке клиента и на странице подписки, в Clash-подписке он идёт как `wireguard` с `amnezia-wg-option`. Подходят AmneziaVPN, AmneziaWG, Clash Meta.
- **MASQUE** (CONNECT-IP поверх HTTP/3 или HTTP/2, всегда TLS). Работает в ядре Xray и обновляется вместе с ним. Можно включить HTTP/3 (UDP), HTTP/2 (TCP) или оба на одном порту. Конфиг выдаётся в JSON-подписке и в карточке клиента, для него нужен клиент на Xray 26+.

Трафик TUIC и AmneziaWG панель передаёт в Xray через локальный мост. Поэтому статистика, лимиты трафика и устройств, сроки, WARP и фильтрация работают для них так же, как для VLESS. TCP- и UDP-инбаунды могут занимать один номер порта, например Reality на TCP 443 и TUIC на UDP 443.

## Форматы подписки

Одна ссылка подписки отдаёт нужный формат сам — по User-Agent приложения. Формат можно задать и явно, параметром `?format=`:

| `format` | Для чего | Что внутри |
|---|---|---|
| — (base64) | Happ, v2rayNG, v2RayTun, Streisand, Hiddify | ссылки `vless://`, `vmess://`, `trojan://`, `ss://`, `hy2://`, `tuic://` |
| `singbox` | sing-box (SFA/SFI/SFM/SFW), Karing, Throne, Hiddify, NekoBox | готовый конфиг sing-box 1.12+: TUN и mixed-прокси `127.0.0.1:2080`, DNS через прокси, «Автовыбор», прямой доступ к локальным сетям и (если включено) к RU-сайтам |
| `clash` | Clash Meta / Mihomo, FlClash, Clash Verge | YAML с TUIC и AmneziaWG |
| `json` | Happ, v2RayTun, v2rayN (Xray-конфиги) | полные конфиги Xray, включая MASQUE |
| `links` | просмотр | ссылки открытым текстом |

Официальные приложения sing-box получают формат `singbox` автоматически. В других (например, в Throne или NekoBox на ПК) добавьте к ссылке `?format=singbox` и импортируйте её как удалённый профиль sing-box.

В конфиг sing-box не попадают XHTTP, MASQUE и AmneziaWG: sing-box их не поддерживает. Не попадает и VLESS Reality, если на сервере Xray 26.9.8 или новее. Такой сервер принимает только ClientHello с ключом X25519MLKEM768, а sing-box (по крайней мере до 1.14.x) этот ключ не отправляет, поэтому подключение всегда завершается ошибкой `reality verification failed` ([SagerNet/sing-box#4520](https://github.com/SagerNet/sing-box/issues/4520)). В Clash-подписке для Reality включён `support-x25519mlkem768: true`, поэтому Mihomo подключается.

## Связка серверов

1. На втором сервере (на нём тоже стоит KVK Panel) откройте «Связка серверов» и скопируйте ключ.
2. На основном сервере: «Связка серверов» → «Добавить сервер», вставьте ключ.
3. После первой синхронизации инбаунды второго сервера выдаются всем клиентам и появляются в их подписках.

Кому какие инбаунды оставить, выбирается в карточке клиента: «Изменить» → «Инбаунды», группа «Сервер «…»». Доступ закрывается и на самом втором сервере, а не только в подписке. Новым клиентам по умолчанию выдаются инбаунды всех серверов, для бота-магазина список задаётся в его настройках. Новый инбаунд на втором сервере получают клиенты, у которых уже есть доступ к этому серверу.

Ключ сервера в консоли показывает `kvk apikey` (или пункт «Ключ связки серверов» в меню `kvk`).

### Управление серверами с основного

В разделах «Инбаунды», «Домены», «Сайт», «Фильтрация» и «WARP» сверху есть выбор сервера. Выберите связанный сервер, и всё настраивается на нём прямо с основного, входить в его панель не нужно. Инбаунд, созданный так на втором сервере, сразу выдаётся всем клиентам, если включено «Выдать всем клиентам». Доступ потом меняется в карточке клиента или кнопками «Выдать всем» и «Забрать у всех». Клиентов создают на основном, на других серверах этого раздела нет.

### Сохранённая конфигурация и восстановление

Основной сервер хранит копию конфигурации каждого связанного: инбаунды с ключами, домены с сертификатами, сайт-прикрытие, фильтрацию, WARP и версию Xray. Доступ к самой панели (порт, путь, логин, токен) в копию не входит. Копия обновляется сама после каждого изменения с основного и раз в 12 часов.

- **Конфиг изменили не через основной.** При синхронизации панель это заметит: появится предупреждение в «Связке серверов», событие и сообщение в Telegram. В окне «Конфигурация» можно оставить то, что сейчас на сервере («Оставить как на сервере»), или вернуть сохранённое («Восстановить на сервере»).
- **Сервер заблокировали.** Поставьте KVK Panel на новый сервер, выполните там `kvk apikey` и скопируйте ключ. На основном откройте «Связка серверов» → карандаш у сервера, вставьте ключ и сохраните. Затем нажмите «Восстановить на сервере». Панель перенесёт на новый сервер инбаунды с теми же ключами, домены, сайт, фильтрацию и WARP, поставит ту же версию Xray и откроет порты. Сертификаты Let's Encrypt для доменов выпускаются заново, когда домен смотрит на новый IP. Если включить «Направить DNS доменов на новый сервер» и в настройках сайта задан токен Cloudflare, панель сама поменяет A-записи. Доступ клиентов к инбаундам сохраняется, подписки обновятся сами.
- Копию можно скачать в JSON кнопкой «Скачать».

## Версия Xray

Нажмите на значок «Xray vX.Y.Z» в шапке панели (или «Версия» на «Обзоре»). Откроется окно со списком релизов, где можно обновиться, откатиться на любую версию или вернуть предыдущую. Если новая версия не запустится с текущим конфигом, панель сама вернёт прежнюю.

## Меню `kvk`

Наберите `kvk` на сервере. В меню можно посмотреть данные для входа, сбросить логин и пароль, сменить порт или путь, отключить 2FA или HTTPS, управлять службой (start, stop, restart, автозапуск), смотреть логи, обновить панель, сменить версию Xray, обновить geo-файлы, сделать бэкап или восстановить его, открыть порт, включить BBR и удалить панель.

Те же действия доступны командами: `kvk start|stop|restart|status|info|reset|update|xray [VER]|geo|backup|restore FILE|bbr|apikey|uninstall`. `kvk apikey` показывает ключ связки серверов, адрес панели и API-токен.

## Разработка

```bash
cd frontend && npm install && npx vite build   # собирает web/dist (коммитится — встраивается через go:embed)
go build -o kvk-panel ./cmd/kvk-panel
./kvk-panel run --data ./data --bin ./bin       # затем ./kvk-panel info
```

Релиз: поднимите `VERSION`, создайте тег `vX.Y.Z` — GitHub Actions соберёт бинарники для amd64/arm64/armv7.
